# Agent report: perf round 2, item 2.4, atomic fast path (measured, dropped)

- **Date:** 2026-09-25
- **Status:** dropped. The part that can be answered before any session with
  unchanged answers is bounded at 0.9% of the replay, under the 3% rule.
- **Scope:** measurement only; no code.
- **Read this if:** you consider answering `ask` from the fact cache or from
  the assumptions' literals before the engine runs.

## Measurement

This was an instrumented replay on the Pi (ad hoc script, not committed). It
wraps `sympy_api._ask`, so it sees only the queries that miss the answer memo,
7,906 of 13,877. For each query whose proposition is a vocabulary atom or its
negation (7,388 queries), it records two things at the time of the query:

- whether that literal, or its negation, is literally a conjunct of the
  assumptions;
- whether the engine's fact cache holds a value for the atom.

The cost of each query is its `ms` from the 0.3 log (`log-d166940.jsonl`,
logged pass 4,380 ms). Every answer still matched the recording.

| class | queries | ms | share | answers today |
|---|---:|---:|---:|---|
| literal (or its negation) is a conjunct of the assumptions | 435 | 41.4 | 0.95% | True 388, False 37, **None 10** |
| of these, reaching a session | 425 | 38.2 | 0.87% | as above minus the 10 |
| atom's value is in the fact cache (and not the above) | 1,502 | 366.7 | 8.37% | mixed, 343 None |
| of these, reaching a session | 1,113 | 220.6 | 5.04% | answered by propagation |
| of these, failing on Uninterpreted assumptions | 389 | 146.0 | 3.33% | None |
| all of the above | 1,937 | 408.1 | 9.3% | |

## Why the bound that counts is 0.9%

A fast path in `sympy_api.ask` "before any session is touched" has to return
exactly what the engine returns today. Two things stop it:

1. **Uninterpreted assumptions answer None.** When the assumptions hold a
   relation no theory interprets (`Q.le(x, pi)`), today's answer is None,
   even for `ask(Q.positive(x), Q.positive(x) & Q.le(x, pi))`. That is 10 of
   the literal cases and 389 of the fact-cache cases. A fast path must first
   know the assumptions are interpretable, which today only building the
   session tells. (Item 2.5 memoizes the failure, which covers exactly these
   queries: 3.4% here.)
2. **Inconsistent assumptions must raise ValueError.** `query_literal` checks
   `implied(assumptions)` on every query, even when the answer is fixed at
   root, mirroring `sympy.ask`. A literal in the assumptions or a cached fact
   says nothing about whether the assumptions are consistent. The check needs
   the session, its propagation and `implied`, and those are most of what a
   propagation-path query costs (median 0.15 ms logged).

   A fact-cache answer can also differ from the session's in principle. A
   fact cached by another session after this session visited the node is not
   a unit in this session, so today's answer can be None where the cache says
   True. That did not occur on the stream, but it would be an answer change.

So the literal case that reaches a session, 425 queries or 0.87%, is the only
class a fast path could answer correctly, and even that still needs the
consistency check. The fact-cache class (5.0%) cannot skip the session without
dropping the ValueError guarantee.

## Decision

Dropped by the bound rule: 0.9% < 3%. The 3.3% of Uninterpreted queries in
this table are 2.5's target and are handled there.

## Risks for review

None (no code). If someone wants the fact-cache 5%, it is a semantic change:
answer from the cache without re-checking the assumptions' consistency. That
is the same kind of decision as issue #8's None memo, and it is for the
orchestrator to make, not a free speedup.
