## Change

`--log` replays the cold pass once with wrappers installed on the classes
(`sympy_api._ask`, `Engine.ask/is_/_is_custom/_context_session/
_fresh_session`, `Session.query_literal/escalate`, `Solver.entails/_solve`)
and writes one JSON line per query. Without `--log` the tool imports
nothing new and runs the same loop as before. With `--log` and repeats > 1,
the later passes are warm and printed as such.

Record format: every key of the AGENT-COMMON.md contract, unchanged, with
these additions (documented in the `tools/query_log.py` docstring):

- `session_new` has one value beyond the four in the contract:
  `"context_free"` (a fresh session per query by design: `Engine.is_`,
  `Engine._is_custom`, `Engine.ask` without assumptions). `"evicted"` also
  covers a rebuild after the session outgrew `session_limit`
  (`evict_reason` is `"lru"` or `"limit"`; on this stream always `"lru"`).
- `solves[]` entries: `target` is read off the literals `entails` passes to
  `_solve` (last literal `¬P` → `"not_p"`, `P` → `"p"`); an entails
  consistency solve (assumptions only) is `"other"` with `role:
  "consistency"`; any other `_solve` caller is `"other"`, `role: "solve"`,
  with `lits`. Extra keys `restarts`, `nvars` (solver variables at the
  call), `nassum` (assumption literals, not counting the target), `depth`
  (only for nested engine queries; none on this stream).
  `model` is taken from `Solver._model` after a satisfiable `_solve`, which
  is exactly the assignment `_search` returned True on.
- per query: `via` (`memo`, `ask`, `is_`, `is_custom`, `is_cache`: the
  fact cache answered `Engine.is_`, `none`: out of scope or trivial),
  `nested` (0 throughout), `built` (sessions built), `session_error`
  (building the contextual session raised; see below).
- `path`: `"propagation"` is appended per `query_literal(search=False)`
  call, so an escalated query reads `propagation>escalation>propagation`.
  The cone session's own `escalate()` is part of the `"cone"` stage and not
  logged as a second `"escalation"`. A query that hits `Uninterpreted`
  before any `query_literal` has an empty path.
- `ms` includes the logging overhead (logged pass 4.81 s vs 4.21 s cold).

Cross-check against `Engine.stats` in the plan: memo 5,971 + `is_cache` 46

## Risks for review

- (Added after batch 2.) `query_log.run()` calls `install()` itself. Before
  the guard, a second `install()` from a script wrapped the entry points
  twice and silently disabled stage tracking (empty `path`, null
  `session_new`). `install()` is now idempotent.

- The wrappers mirror control flow in `Engine.ask` (a `_fresh_session`
  call after a `propagation` stage is read as the cone) and in
  `Solver.entails` (target tagging by the last `_solve` literal). If
  either changes (items 1.1, 1.2), the log mislabels silently; check the
  cross-check totals above against `Engine.stats` after such a change.
- `session_new "evicted"` for the 1,067 Uninterpreted rebuilds is
  technically "seen before, not in the LRU"; read `session_error` to tell
  them apart.
- Orchestrator: the 1,130 failed session builds are a cheap engine-side
  target (a negative memo of "these assumptions are uninterpreted" keyed
  like `_context_sessions`, valid under the same registry state), bound
  about 12% of the replay. It is not in the plan's item list; it belongs
  next to 2.1.
