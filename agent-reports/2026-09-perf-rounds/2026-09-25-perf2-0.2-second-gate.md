## The gate

    python tools/gate2.py CHECKOUT [--frozen PATH] [--sympy PATH]      # check, exit 1 on any change
    python tools/gate2.py CHECKOUT --freeze RECORDED.jsonl [--frozen OUT]

It replays every `ask`/`rec` record in recording order through
`satassume.sympy_api.ask` with one fresh `Engine`, in a subprocess whose
`PYTHONPATH` is CHECKOUT plus the SymPy pin (so any checkout, including
old commits, can be gated), and compares with the frozen answers. Defaults
fit the local machine (`~/.cache/satassume/gate2-frozen.jsonl`,
`/home/tilo/sympy`); on the Pi pass `--frozen
/work/src/bench/gate2-frozen.jsonl --sympy /work/src/sympy-pin`.

It gates **all** 2,863 replayable records, not only the 2,588 in scope,
because satassume also answers the relation records (theory adapters) and
a change there is a behaviour change too; the in-scope count of changes is
printed separately. 7 records cannot be rebuilt from `srepr` and are left
out of the frozen file.

Counts: 2,863 records; in scope 2,588; out of scope matrix 189, relation
78, other 8. In-scope answers (frozen) against SymPy's recorded answers:
agree 2,487, extra (definite where SymPy said None) 26, none 70, error 5
(ValueError on assumptions contradicting declared facts, the documented
choice), **wrong 0**. Relation records: agree 75, none 3.

Time: freeze 2.05 s on the Pi (1.16 s inside `ask`); a check 2.1 s on the
Pi, 2.0 s locally, about 3 s with process start.

## Issue #8, question 1: does caching `None` answers change any answer here?

**No.** `b3d429b` and `cbb971f` agree on all 2,863 records, and so does
`328bdbb` itself. To make sure the distribution exercises the memo at all,
the `d166940` code was also replayed once as is and once with
`AnswerMemo.put` patched to skip `None` (ad hoc script, not committed): the
replay has 726 memo hits, 238 of them `None`; without memoizing `None`
those 238 are recomputed and every answer is still identical to the frozen
one. So on this distribution the first `None` never turns definite later,
and the memo's order-independence costs nothing. (The refine stream showed
the same; the case issue #8 describes, a repeat decided after other
queries grounded more nodes into the same session, occurs on neither
workload.)

## Risks for review

- The frozen answers are satassume's, not SymPy's: the gate catches any
  change, including an improvement (a None becoming True). An intended
  improvement means re-freezing with `--freeze` and saying so in the
  commit.
- Recording order matters (one engine for the whole replay, as in
  `tools/compare.py`); do not sort or dedupe the file.
- `rebuild` has a 2 s SIGALRM guard per record; on an overloaded machine
  a slow rebuild would show up as a changed answer (`unreplayable`), not
  a silent pass.
