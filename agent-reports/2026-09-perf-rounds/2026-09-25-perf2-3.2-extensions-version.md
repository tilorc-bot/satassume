# Agent report: perf round 2, item 3.2, a version counter on `Extensions`

- **Date:** 2026-09-25
- **Status:** done, kept (a cleanup, done regardless of the measurement, as the plan says).
- **Scope:** `satassume/extensions.py`, `satassume/sympy_api.py` (`_registry_state`),
  `tests/test_extensibility.py` (one new test).
- **Read this if:** you touch the answer memo of `sympy_api.ask`, or register
  clause-generating functions in some way other than `Extensions.register`.

## Measurement

None needed by the plan. On the refine stream the handler dict is empty, so
the old per-call snapshot (`tuple((k, tuple(v)) for k, v in h.items())`) was
already cheap; no speed change was expected, and none shows.

## Change

`Extensions.version` is bumped by every `register` (each decorated function)
and every `unregister`. The memo state is now `(registry, registry.version,
tuple(engine.relation_specs))`; the registry object is compared by identity,
so swapping `engine.extensions` also clears the memo. Before, the handler
lists were snapshotted by value on every call.

Correctness: an answer depends on the registrations only through the
registry's handler lists, which change only in `register`/`unregister`, and
both bump the version. So the memo is cleared whenever the old snapshot would
have differed. The new state is strictly more conservative: re-registering the
same function after an unregister also clears the memo, which the value
snapshot would not have done.

## Risks for review
